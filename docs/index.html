v0.98.4 · sessions open in auto mode, bypass locked

Claude Code, on autopilot.

Five levels of hands-off work. A gate on every one.

8sync is one Rust binary. It installs Anthropic's Claude Code with a kit that plans, codes, tests, reviews and commits by itself, and refuses what you never want an agent to do: delete outside the repo, print .env, force-push, or open in bypass mode.

Linux · macOS your system curl -fsSL https://get.8syncdev.com/install | sh
Windows your system irm https://get.8syncdev.com/install.ps1 | iex

Then, in any repo, 8sync ccc . core opens a Claude Code session named core with the kit. Type /ship and a task.

Pick how far it goes without you

Type one of these inside Claude Code. Each one runs longer before it needs you. You start levels 3 to 5; an agent can't start them on its own.

  1. 1one edit
    /do <task>

    A change of three files or fewer. No plan, no commit.

    Needs you to look at the diff and commit.

  2. 2to commit
    /ship <task>

    One feature or bug: plan, research, code, test, UAT, review, CHANGELOG and memory, then a commit on a branch.

    Needs you to push. It never pushes.

  3. 3to release
    /ship-auto <task>

    /ship, then a PR, CI green on Windows, macOS and Linux, merge, tag and release.

    Needs you for one Ship answer that lists every step.

  4. 4until green
    /ship-loop <goal>

    Writes acceptance checks, then repeats until every check exits 0. Stops at 12 iterations, 90 minutes, or the same failure twice.

    Needs you when a cap is hit, or to release.

  5. 5the backlog
    /autopilot

    Works through labelled GitHub issues, the Next list in su-code/STATE.md and unguarded failures, each item as its own loop on its own branch. Up to 5 items or 8 hours.

    Needs you for one Ship answer for the whole batch.

Every level runs through the same rails below, and every "done" in its report carries the command it ran and the output it got. No output, and the report says "not verified".

Armed in every mode

The kit's hooks run before and after each tool call, in auto mode and under claude -p. They ship inside the 8sync binary; the guard adds about 9 ms per call.

  • Guard

    Denies deleting the root, your home or the project, disk wipes, force-push in any spelling, and printing or uploading .env and keys. Asks before deletes outside the project.

  • Verify

    After every edit, cargo check, typecheck or go vet runs in the background. Only a failure comes back, and a turn can't end on a broken build.

  • Stop gate

    Claude can't end a turn on a plan it hasn't carried out ("Next I'll…") or on a routine "shall I proceed?". Your "stop" or "dừng" always ends it.

  • Ask gate

    Before a question reaches you, Sonnet checks it. Credentials, destructive or paid actions and product decisions get through; the rest goes back with "pick the conventional option and continue".

  • Ship grant

    Push to main, merge, tag, release, publish and deploy wait for one Ship answer that lists every step. Approve once and that session holds the grant for 8 hours.

  • No bypass

    A launcher's --dangerously-skip-permissions is rejected. The session opens in auto mode, with every lamp on this panel still lit.

The guard is a seat belt, not a sandbox: a program that deletes files itself (python -c, a build script) is not inspected. Limits are listed in the README.

Or switch on the whole project

Every Claude Code session you open in a repo is a room, and its name is its role: lead, api, qa, rd. One command gives every room a loop and a shared queue of targets.

terminal, inside the repo 
# every room gets a 10-minute loop; --team fills rd, qa, reviewer
$ 8sync ccc auto on --here --loop 10m --team

# a target is done when its check exits 0
$ 8sync ccc auto add "fix login refresh" --check "pnpm test auth"

# urgent: front of the queue, into every room now
$ 8sync ccc auto add "webhook 500 on retry" --now

# ▶ working · ✓ done · ✗ dropped
$ 8sync ccc auto queue

# stop (or: auto off · 8sync ccc cancel)
$ 8sync ccc auto pause
  • lead splits
  • dev ships
  • qa checks
  • reviewer reviews
  • rd unblocks
  1. On each tick, every room takes the part of the head target that fits its role. Dev work goes through /ship, with tests, review and the security gates.
  2. When the target's check exits 0, a room records auto done <id> with --evidence "<command: result>" and the team moves to the next target.
  3. With the queue empty, rooms pick work from .claude/loop.md and the Next list in su-code/STATE.md.

No command needed inside a room: say đưa vào loop: … (add to the loop) or làm ngay: … (do it now) and Claude queues it.

Headless, no window open

claude -p "/autopilot --max-items 5 --hours 8" --permission-mode auto --permission-prompts none --max-budget-usd 20

A headless run can't answer the Ship question, so the batch stops before any merge and leaves a brief. Anything that would prompt is denied, not approved.

Limits that hold it in check

  • On a Claude subscription, auto holds a lease of at most 4 hours and runs while you're around. For runs over days, use Claude Code Routines (/schedule) or a Console API key.
  • A spend ceiling (default $5 an hour, from the cost Claude Code reports) skips ticks once it's reached.
  • Claude Code removes a loop after 7 days; run the command again to extend it.

Opens in auto. Never in bypass.

Some launchers start Claude Code with --dangerously-skip-permissions (Orca's default arguments did), and a launch flag outranks your settings. That turned off the auto-mode classifier for every session it opened.

Since v0.98.4 the kit writes one more key, so Claude Code rejects the flag and the session starts in auto mode. The kit only fills keys you haven't set, and 8sync ccc policy prints the same lock for managed settings across an org.

// ~/.claude/settings.json, from 8sync ccc kit
"permissions": {
  "defaultMode": "auto",
  "disableBypassPermissionsMode": "disable"
}

Checked on Claude Code 2.1.296: a session launched with the bypass flag reported "permissionMode":"auto".

Method, task list and the other runs

Install

No git, Rust or admin rights. One file, 4.9 MB (macOS arm64) to 7.0 MB (Linux x86_64) in v0.98.4. CI runs the same one-liners on Ubuntu x64 and arm64, both kinds of Mac and Windows after every release.

  1. Run one line

    Linux · macOS your system curl -fsSL https://get.8syncdev.com/install | sh
    Windows your system irm https://get.8syncdev.com/install.ps1 | iex

    It checks the binary's sha256, then sets up gh, omp, codegraph, Forge with zsh, Claude Code with the kit, 50+ skills and MCP servers. Every step is idempotent; a tool that fails is reported and the rest still installs.

  2. Open a named session

    cd your-repo && 8sync ccc . core

    Each name is one conversation per repo, so 8sync ccc . core tomorrow continues today's thread. Sign in with your Claude plan the first time.

  3. Hand it a task

    Type /ship add retry to the webhook client, or any level from the ladder above.

  4. Stay current

    8sync up installs a new release with a sha256 check; 8sync ccc also updates on launch. 8sync doctor checks the whole setup.

8sync forge <name>

## Answers by question (facts only)
1. Stop/SubagentStop contract: S1-S12. Output: `decision:"block"` + `reason`, or exit 2 + stderr, or `hookSpecificOutput.additionalContext`; `continue:false` ends processing (S9). Loop limits: `stop_hook_active` + 8-consecutive cap reset by tool calls (S2, S3). `-p`: no dedicated doc, indirect evidence S16.
2. Official plugins: ralph-loop (S31), hookify stop rule (S30), security-guidance (S33), /goal (S35).
3. PreToolUse: S18-S29. Official dangerous-command examples are regex/substring only (S27-S29).
4. Interrupts: S1, S13-S15; no official "user said stop" signal.
5. Recommendations below (analysis derived from evidence).

## Recommendations for a native Rust Stop gate + destructive-command guard (derived, not a final conclusion)

Stop gate
- R1. If `stop_hook_active == true` exit 0 with no output, first thing (S2, S33a, S3).
- R2. Use `last_assistant_message`, fall back to transcript only when absent (S4); ralph-loop and hookify still parse the transcript (S30, S31).
- R3. Gate only on objective cheap signals; fail-open on parse/IO error (S31c, S30, S22). Allow when SubagentStop `agent_type` is empty (S11).
- R4. Own per-session counter with TTL, capped below 8 (e.g. 2-3) as in S33b, because the platform counter resets on any tool call (S3) and cannot bound a loop where each continuation calls a tool.
- R5. If `background_tasks` or `session_crons` non-empty, the session is paused, not done (S5): do not block for "incomplete".
- R6. `additionalContext` for advisory nudges (S6); `decision:"block"`+`reason` for hard gates. Stdout must start with `{` and contain only JSON (S26); a native binary avoids shell-profile pollution.
- R7. Under `-p`: Stop continuation works (indirect, S16); async hooks are cancelled at teardown (S16), so keep the gate synchronous. Not verified: output when the cap is hit in `-p`.
- R8. Interrupt: Stop does not fire on user interrupt (S1), so no special handling needed; "user said stop" in text has no official signal (S15). Optional design (UNVERIFIED as practice): UserPromptSubmit hook records a flag from the prompt, Stop gate allows stop when flag is set.
- R9. StopFailure (API error) never reaches the gate (S13).
- R10. Do not block merely because a string such as "cargo test" is absent from the transcript (hookify false-positive pattern, S30); verify state yourself (e.g. git status of changed files since a baseline, as security-guidance does, S33c).

Destructive-command guard
- R11. Matcher `Bash|PowerShell` (S24); on Windows without Git Bash only PowerShell exists. Read `tool_input.command` for both.
- R12. Emit `permissionDecision:"deny"` + `permissionDecisionReason` (S18, S28) or exit 2 + stderr (S21). Prefer deny over `ask` (ask auto-denied in `-p`, S20; in auto mode ask forces prompt, S19), avoid `defer` (honoured only in `-p`, S20). Non-matches: exit 0, empty output so normal flow applies (S21). Never emit `allow` from a guard (S18).
- R13. Parse rather than substring: tokenize, split on `;`, `&&`, `||`, `|`, newlines; unwrap `sudo`, `env`, `bash -c`, `cmd /c`, `powershell -Command`; handle flag permutations (`-rf`, `-fr`, `-r -f`, `--recursive --force`), `Remove-Item -Recurse -Force`, `rd /s /q`, `del /s`, `git reset --hard`, `git clean -fdx`, `git push --force`, SQL `DROP`, `mkfs`, `dd of=/dev/`. Official examples cover only `rm -rf` style (S27-S29) and the official validator's `^` anchor misses compound commands (S27).
- R14. Timeouts fail open (S22): keep the guard fast (native Rust) and set a short `timeout`. Malformed input -> exit 0; matched destructive -> deny.
- R15. Defence in depth: also ship `permissions.deny` rules; docs recommend the permission system for hard deny (S23, S37), and critical-path `rm` is blocked by Claude Code regardless of hooks (S23).
- R16. Windows: normalise `\` to `/` before path comparisons (S25). `-p` sessions treat repo-committed hooks as trusted (S17); a kit guard in user/managed settings is unaffected.

## Contradictions between sources
- C1. Docs (hooks.md:2764-2790) document `hookSpecificOutput.additionalContext` for Stop/SubagentStop, while security-guidance (security_reminder_hook.py:244-256) says there is NO `Stop` member in that union and that emitting it fails `isSyncHookJSONOutput` validation on the asyncRewake path. Possibly different code path or stale comment; not verified by running.
- C2. Docs say check `stop_hook_active` to avoid loops (S2) but official ralph-loop (S31) and hookify (S30) do not read it; they rely on max_iterations / the platform cap.
- C3. hookify says "ALWAYS exit 0" and signals via JSON; docs also allow exit 2 (S7). Both valid.
- C4. Cap wording: hooks.md says count "resets each time Claude calls a tool"; hooks-guide says "eight times in a row with no tool call". Consistent, but a tool-calling loop is not bounded by the cap.

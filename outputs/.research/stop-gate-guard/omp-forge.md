## Ideas to borrow (inputs for synthesis, not conclusions)

(a) Native no-LLM Stop gate (Claude Code Stop hook)
1. Check order as OMP S1: user abort first (never block on interrupt), then structural checks (open todos), then text heuristics, then caps, fail-open on errors.
2. Open-todo check from the transcript's latest TodoWrite state; block with a reminder listing items (S2). Use Forge's dedup (S26): do not re-block if the latest gate reminder in the transcript lists the identical todo set. Add OMP's "awaiting progress" rule (S3): require a tool_use after the last reminder before blocking again; cap ~3 (remindersMax=3).
3. "Awaiting user answer" exemption by regex on last lines (S4), including non-ASCII shortcut for Vietnamese and cue verbs; option bullets + question counts.
4. Announce-then-stop without LLM: OMP does it only in smart mode via LLM (S5/S6), so no regex to copy. Use judge examples in CA/prompts/judge/unexpected-stop.json as test-corpus seeds. Design sketch (own, unverified): last paragraph has future-intent phrase (EN "let me/I'll/next I/doing that now"; VI "để mình/mình sẽ/tiếp theo") AND last assistant message has no tool_use AND no completion marker. Always-on cheap case from "mechanical" mode: empty/thinking-only final turn.
5. Routine permission questions: OMP exempts trailing user-directed questions from the todo reminder (S4) but its judge labels "Should I do that for you?" as unexpected (S6). A gate needs its own rule: question about irreversible/ambiguous choice -> allow stop; question asking permission to do the already-requested work -> block.
6. Block message: short, imperative, with attempt counter (S7), plus "if no work remains say so; do not invent work".
7. Caps: 3 per reminder kind, 8 per hook continuation chain (S9).
8. Skip gate for: forced tool choice, plan mode, sub-agents, pending background work (S1, S2, S9).

(b) Rust Bash/PowerShell destructive-command guard
1. Layering (S13-S18): hard deny/ask list not overridable by broad allow ("prompt-gated unless explicitly denied", S17); allow rules match whole command and never a command with shell control chars (S18); deny/prompt per segment.
2. Command-position anchoring for shutdown/reboot-type words (S15) to avoid `npm run reboot-tests`/`echo 'shutdown ...'` FPs.
3. `rm` must tolerate flags before/after, `--`, long flags (S15/S17) and extend beyond `/` to `~`, `$HOME`, `.`, `*`, drive roots (gap S16).
4. Parser: OMP TS tokenizer is admittedly partial (S19); its Rust side uses a real bash parser (`brush-parser`, S21) post-expansion. A Rust hook could use a tokenizer plus optional `brush-parser`; tree-sitter-bash not used by OMP.
5. Git destructive set (S21): stash, reset --hard / to other commit, checkout/switch/restore whole-tree or forced; `clean -fd`, `push --force` are my additions, not from OMP.
6. Test corpus shape (S17): table-driven positives + benign list + allow-does-not-override-critical + compound chains.
7. PowerShell/cmd: no source in either repo (S22, S34); patterns such as `Remove-Item -Recurse -Force`, `rd /s /q`, `del /f /s /q`, `format`, `iex (iwr ...)`, `-EncodedCommand` would be new design, not verified here.

Pitfalls (evidence-backed)
- P1 OMP yolo mode ignores the critical-pattern prompt (S14): guard must be mode-independent (in Claude Code, a hook deny/ask).
- P2 Whole-string glob rules (Forge, S33) let an allow ride `&& rm -rf /`.
- P3 Wrapper bypass: OMP admits `xargs git`, `sh -c`, absolute-path git are not judged (S21); control chars inside quotes matter because of `-c`/`-e` reinterpretation (S18).
- P4 Reminder/ack loop: fixed in OMP only after issue #2590 (S3); gate must require tool-level progress between blocks or dedup (S26).
- P5 Never block/continue after user abort; stale verdicts dropped on generation change (S11, S6).
- P6 Over-broad destructive regexes cause FPs; OMP keeps list "intentionally tight" (S15).
- P7 English word-list question heuristics; OMP's non-ASCII shortcut treats any non-ASCII `?` line as a question (S4).

## Contradictions between sources
- OMP judge examples classify "Should I do that for you?" as an unexpected stop (S6) while the todo gate treats a trailing user-directed question as legitimately awaiting an answer (S4); different code paths, not reconciled.
- Forge shell doc comment claims absolute-path/`cd` protection; code does not implement it (S31).
- OMP ships a "Critical pattern" list but its default approval mode is `yolo` where it is inactive (S13/S14).

## D. Hooks (S4 unless noted)
41. Exit codes — S4#exit-code-output — "Success: your hook exits 0." "Blocking error: your hook exits 2. On events that can block, Claude Code stops the action." "Non-blocking error: any other code ... The action goes ahead" — high
42. Exit-2 table (S4#exit-code-2-behavior-per-event) — PreToolUse "Blocks the tool call"; UserPromptSubmit "Blocks the prompt, so it never reaches Claude."; Stop "Prevents Claude from stopping, continues the conversation"; SubagentStop "Prevents the subagent from stopping"; TeammateIdle "Prevents the teammate from going idle, so it continues working"; TaskCreated "Rolls back the task creation"; TaskCompleted "Prevents the task from being marked as completed"; PostToolUse "Shows stderr to Claude; the tool already ran" (cannot block); SubagentStart "Shows stderr to user only" — high
43. JSON decision (S4#decision-control) — UserPromptSubmit/PostToolUse/Stop/SubagentStop etc: top-level `decision:"block"`+`reason`; "Stop and SubagentStop also accept hookSpecificOutput.additionalContext for non-error feedback that continues the conversation"; PreToolUse: `hookSpecificOutput.permissionDecision` allow/deny/ask/defer + `permissionDecisionReason`; SessionStart/SubagentStart: context only — high
44. UserPromptSubmit — S4#userpromptsubmit-decision-control — "can't replace the prompt; it only injects additionalContext alongside it." "Plain stdout and the additionalContext value are each injected as a system reminder that starts with the hook's name; Claude reads both." No visible transcript entry — high
45. Stop — S4#stop-input — "`stop_hook_active` is true when Claude Code is already continuing as a result of a stop hook." "Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn. The count ... resets each time Claude calls a tool. To raise the cap, set CLAUDE_CODE_STOP_HOOK_BLOCK_CAP." — high
46. SubagentStop — S4#subagentstop — "Returning decision: "block" with a reason keeps the subagent running and delivers reason to the subagent as its next instruction." "To inject context into the parent session after a subagent returns, use a PostToolUse hook on the Agent tool instead." — high
47. PreToolUse matches Agent — S4#pretooluse — "Matches on any tool name except EndConversation: built-in tools such as Bash, ..., Agent, Workflow, ..." Agent tool_input fields: prompt, description, subagent_type, model — high
48. SubagentStart — matcher = agent type ("general-purpose, Explore, Plan, custom agent names"); exit 2 shows stderr to user only; context-only decision — high
49. TeammateIdle — S4#teammateidle — input `teammate_name`; `team_name` "Deprecated ... will be removed"; `agent_id` "May be absent. Requires v2.1.290 or later". Exit 2: "the teammate receives the stderr message as feedback and continues working instead of going idle." JSON `{"continue": false,"stopReason"}` "stops the teammate entirely" — high
50. TaskCreated — "don't support matchers"; exit 2 or `{"decision":"block","reason"}` -> "Claude Code deletes the task and returns your message to Claude as the tool's error. ... ignores continue:false" — high
51. TaskCompleted — "Exit code 2: the task is not marked as completed and the stderr message is fed back to the model"; `continue:false` stops teammate only when a teammate finishing its turn triggered it; "When the TaskUpdate tool triggered the event, Claude Code ignores continue: false; exit code 2 still blocks" — high
52. asyncRewake — S4 (async section) — "an asyncRewake hook that exits with code 2 wakes Claude immediately even when the session is idle." "Claude Code doesn't enforce timeout on [async hook] ... still enforces timeout on a hook you run with asyncRewake." Async output "delivered on the next conversation turn" — high
53. Steering lead to delegate via hooks (DESIGN INFERENCE, not a doc claim): documented levers = UserPromptSubmit additionalContext (inject "delegate to X"), PreToolUse deny with `permissionDecisionReason` on Edit/Write/Bash (forces Claude to see reason), Stop `additionalContext`/block (8-cap), PostToolUse on `Agent` for result context. No documented hook can itself spawn an agent — med (inference)

## G. Contradictions / drift vs earlier local notes and assumptions
- Common assumption "subagents cannot spawn subagents" is FALSE in 2.1.299 docs (S1: default depth three; env var to change). Earlier versions differed (v2.1.217-218 default 1). Any harness design relying on flat hierarchy must set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1.
- no-idle-office.md says Stop cap "native 8" — matches S4#stop-input. Its claim "asyncRewake" matches S4 line. Consistent.
- Task tools default only on "Opus 4.7, Sonnet 4.6, Haiku 4.5 and earlier" (S5) whereas S3 mentions Opus 5.5/Sonnet 5.5/Haiku 5.5/Fable exist -> shared task list may be EMPTY on 5.x models unless CLAUDE_CODE_ENABLE_TODO_TOOLS=1. Self-claim therefore depends on that. Not verified on a live 2.1.299 session.
- S1 teammate `run_in_background` error text vs S2 "either with an error or by running silently in the foreground": slight wording difference; S2 refers to S1 for the rules.
- S2 comparison table says subagents give "Lower" token cost; S3 gives only the conditional "~7x in plan mode" for teams; no unconditional multiplier.

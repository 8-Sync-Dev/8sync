omp router

API tương thích OpenAI và Anthropic cho người trong 8 Sync, chạy trên VPS OVH bằng omp auth-gateway. Client chỉ cầm key của router; key thật của nhà cung cấp nằm trong kho của VPS và không bao giờ đi ra ngoài.

Tổng quan

Base URL (OpenAI)
https://vps.8syncdev.com/omp-router/v1
Base URL (Anthropic SDK)
https://vps.8syncdev.com/omp-router (SDK tự thêm /v1/messages)
Xác thực
Authorization: Bearer <key>. Header x-api-key bị từ chối (401).
Định dạng
OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, kèm streaming (SSE)
Model
Mọi model của nhà cung cấp đã đăng nhập trên VPS. Hiện có: Z.ai GLM (danh sách)
Kiểm tra sống
https://vps.8syncdev.com/omp-router/healthz (không cần key)
Giao thức
HTTPS qua Caddy, có HTTP/2 và HTTP/3 (Caddy báo Alt-Svc: h3, client hỗ trợ tự chuyển)

Đường đi của một request: client → Caddy (TLS, cổng 443) → socket /run/omp-gw/gw.sock → omp auth-gateway (loopback) → nhà cung cấp. Router cộng thêm khoảng 2 ms so với gọi thẳng Caddy (đo ngày 23/10/2026: /healthz p50 24,1 ms, qua gateway 25,9 ms); thời gian còn lại là của model.

Sơ đồ hoạt động

Một request đi qua bốn chặng, tất cả trên cùng VPS. Phần router (proxyd + gateway) thêm khoảng 1,8 ms so với gọi thẳng Caddy (p50 đo 23/10/2026); một câu trả lời model mất cỡ 2,3 s, nên tốc độ do nhà cung cấp quyết định, không do router.

Không chặng nào là Rust: Caddy viết bằng Go và đã trả lời qua HTTP/3, omp là binary của chính omp, proxyd là của systemd. Viết lại chặng nào bằng Rust cũng chỉ bớt được phần nhỏ của 1,8 ms đó.

Các việc chạy nền, không cần người trực:

Lấy key

Key do owner cấp, mỗi người hoặc mỗi ứng dụng một key. Owner chạy lệnh trên VPS, qua terminal web hoặc SSH (lệnh tự dùng sudo):

Tạo key chỉ gọi được 2 model của gói Coding Plan (in ra đúng một lần; nên dùng mặc định)

omp-gw key add ten-nguoi-dung --models zai/glm-5.3,zai/glm-5.3-flash

Key gọi mọi model (cẩn thận: gồm cả model tính vào số dư tài khoản và model của nhà cung cấp thêm sau)

omp-gw key add ten-khac

Liệt kê, thu hồi

omp-gw key ls
omp-gw key rm ten-nguoi-dung
  • Key có dạng ogw_…. VPS chỉ lưu SHA-256 của key, nên làm mất key thì không lấy lại được: thu hồi rồi tạo key mới.
  • Key mới chạy được sau tối đa 10 giây; key bị thu hồi bị từ chối từ request kế tiếp, cũng trong 10 giây.
  • Không có --models: key gọi được mọi model router đang phục vụ, kể cả model của nhà cung cấp được đăng nhập thêm sau này.

Gọi thử bằng curl

Đặt key vào biến môi trường một lần, các ví dụ dưới đều đọc từ đó:

bash / zsh

export OMP_ROUTER_KEY='ogw_...'

PowerShell

$env:OMP_ROUTER_KEY = 'ogw_...'

Danh sách model key này được gọi

curl -s https://vps.8syncdev.com/omp-router/v1/models \
  -H "Authorization: Bearer $OMP_ROUTER_KEY"

Chat Completions

curl -s https://vps.8syncdev.com/omp-router/v1/chat/completions \
  -H "Authorization: Bearer $OMP_ROUTER_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"zai/glm-5.3-flash","max_tokens":256,
       "messages":[{"role":"user","content":"Chào bạn"}]}'

Streaming (SSE)

curl -sN https://vps.8syncdev.com/omp-router/v1/chat/completions \
  -H "Authorization: Bearer $OMP_ROUTER_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"zai/glm-5.3-flash","stream":true,"max_tokens":256,
       "messages":[{"role":"user","content":"Đếm từ 1 đến 5"}]}'

Anthropic Messages

curl -s https://vps.8syncdev.com/omp-router/v1/messages \
  -H "Authorization: Bearer $OMP_ROUTER_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"zai/glm-5.3-flash","max_tokens":256,
       "messages":[{"role":"user","content":"Chào bạn"}]}'

OpenAI Responses

curl -s https://vps.8syncdev.com/omp-router/v1/responses \
  -H "Authorization: Bearer $OMP_ROUTER_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"zai/glm-5.3-flash","max_output_tokens":256,"input":"Chào bạn"}'

Trên Windows dùng curl.exe trong PowerShell, đổi $OMP_ROUTER_KEY thành $env:OMP_ROUTER_KEY, và viết JSON trong file rồi gửi bằng -d "@body.json" để tránh lỗi dấu nháy.

Dùng với SDK

Các đoạn dưới đã chạy thật qua router ngày 23/10/2026 (openai và anthropic bản mới nhất trên PyPI, openai trên npm).

Đọc quy tắc trước khi dùng SDK. Model zai/* hiện chạy trên gói GLM Coding Plan, mà Z.ai chỉ cho dùng trong các công cụ lập trình được hỗ trợ. Script hay sản phẩm tự viết cần owner thêm API key Z.ai trả theo token trước.

Python, OpenAI SDK (pip install openai)

import os
from openai import OpenAI

client = OpenAI(
    base_url="https://vps.8syncdev.com/omp-router/v1",
    api_key=os.environ["OMP_ROUTER_KEY"],
)
r = client.chat.completions.create(
    model="zai/glm-5.3-flash",
    max_tokens=256,
    messages=[{"role": "user", "content": "Chào bạn"}],
)
print(r.choices[0].message.content)

# streaming
for chunk in client.chat.completions.create(
    model="zai/glm-5.3-flash", max_tokens=256, stream=True,
    messages=[{"role": "user", "content": "Đếm từ 1 đến 5"}],
):
    if chunk.choices:
        print(chunk.choices[0].delta.content or "", end="", flush=True)

Python, Anthropic SDK (pip install anthropic)

import os
import anthropic

client = anthropic.Anthropic(
    base_url="https://vps.8syncdev.com/omp-router",
    auth_token=os.environ["OMP_ROUTER_KEY"],  # gửi Authorization: Bearer
    api_key=None,                            # không gửi x-api-key
)
m = client.messages.create(
    model="zai/glm-5.3-flash",
    max_tokens=256,
    messages=[{"role": "user", "content": "Chào bạn"}],
)
print(m.content[0].text)

JavaScript / TypeScript (npm i openai)

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://vps.8syncdev.com/omp-router/v1",
  apiKey: process.env.OMP_ROUTER_KEY,
});
const r = await client.chat.completions.create({
  model: "zai/glm-5.3-flash",
  max_tokens: 256,
  messages: [{ role: "user", content: "Chào bạn" }],
});
console.log(r.choices[0].message.content);

Công cụ khác (Cursor, Continue, LangChain, LiteLLM…): chọn kiểu "OpenAI compatible", base URL https://vps.8syncdev.com/omp-router/v1, API key là key của bạn, model ghi đủ nhà-cung-cấp/model.

Dùng với omp

Thêm vào ~/.omp/agent/models.yml trên máy bạn, rồi đặt biến môi trường OMP_ROUTER_KEY như phần Gọi thử.

apiKey: OMP_ROUTER_KEY là tên biến môi trường. Nếu shell chưa có biến đó, omp gửi nguyên chữ OMP_ROUTER_KEY làm key và mọi request nhận 401 (omp còn tự thử lại vài lần). Gặp 401 thì kiểm echo $OMP_ROUTER_KEY trước.

Cách 1: provider OpenAI-compatible riêng (khuyên dùng)

Thêm một provider mới tên omp-router; model hiện dưới tên omp-router/zai/…. Provider zai sẵn có trên máy bạn không bị đụng, và key Z.ai của bạn (nếu có) không bao giờ bị gửi tới router.

models.yml

providers:
  omp-router:
    baseUrl: https://vps.8syncdev.com/omp-router/v1
    apiKey: OMP_ROUTER_KEY
    api: openai-completions
    discovery:
      type: openai-models-list

Chạy thử

omp -p --model omp-router/zai/glm-5.3-flash "Chào bạn"

Cách 2: pi-native (chỉ cho máy chưa đăng nhập Z.ai)

omp gửi request ở định dạng gốc của nó tới /v1/pi/stream. Tên provider phải trùng nhà cung cấp trên router (zai), nên cấu hình này ghi đè provider zai của máy bạn.

Máy đã đăng nhập Z.ai (/login trong omp) thì đừng dùng cách này. Thử ngày 23/10/2026: omp gửi key Z.ai đã lưu tới router trước (nhận 401), rồi mới dùng OMP_ROUTER_KEY. Biến ZAI_API_KEY thì không ảnh hưởng.

models.yml

providers:
  zai:
    baseUrl: https://vps.8syncdev.com/omp-router
    apiKey: OMP_ROUTER_KEY
    transport: pi-native

Chạy thử

omp -p --model zai/glm-5.3-flash "Chào bạn"

Model

Luôn ghi đủ nhà-cung-cấp/model. Tên trần (glm-5.3) cũng chạy nhưng router chọn bản đầu tiên trùng tên, có thể khác cấu hình. Danh sách thật luôn lấy từ GET /v1/models; ngày 23/10/2026 router phục vụ 18 model Z.ai:

Chỉ zai/glm-5.3 và zai/glm-5.3-flash nằm trong gói Coding Plan. Z.ai ghi: "Only the following two models can be called: GLM-5.3, GLM-5.3-Flash" (FAQ, đọc 23/10/2026), trong câu trả lời về việc số dư tài khoản vẫn bị trừ. 16 model còn lại router vẫn liệt kê, nhưng gọi chúng có thể bị tính vào số dư tài khoản Z.ai thay vì hạn mức gói. Theo dõi usage

Router ghi số request, token và chi phí theo header nhận diện client gửi kèm. Gửi tên ứng dụng của bạn để owner tách được usage:

Header khuyên gửi

x-omp-app: ten-ung-dung

Python, OpenAI SDK

client = OpenAI(
    base_url="https://vps.8syncdev.com/omp-router/v1",
    api_key=os.environ["OMP_ROUTER_KEY"],
    default_headers={"x-omp-app": "ten-ung-dung"},
)

Owner xem trên VPS:

24 giờ qua (đổi bằng --hours)

omp-gw usage
omp-gw usage --hours 168

Lệnh in hai bảng: request, token và USD theo ứng dụng; rồi hạn mức của từng tài khoản nhà cung cấp (ví dụ hạn mức token 5 giờ của Z.ai) cùng giờ reset. Key của client gọi /v1/usage sẽ nhận 403: chỉ owner xem được hạn mức chung.

Xem trực tiếp (owner, trên VPS)

omp đã tự ghi đủ dữ liệu; các lệnh dưới chỉ đọc ra. Chạy qua SSH (ubuntu) hoặc terminal web (agent, có sudo). Số liệu bắt đầu từ ngày 23/10/2026, khi router chuyển sang kho riêng; số trước đó nằm ở kho cũ của agent.

Nội dung prompt và câu trả lời không được lưu ở đâu cả: log chỉ có metadata ở trên.

Từng request, cập nhật liên tục (Ctrl+C để thoát)

sudo tail -n 20 -F /home/omprouter/.omp/logs/omp.$(date -u +%F).$(systemctl show -p MainPID --value omp-auth-gateway).log \
  | grep --line-buffered '"auth-gateway request"' \
  | jq -r '[.timestamp[11:19], .client // "(admin)", .format, .model, (if .stream then "stream" else "-" end), .peer] | @tsv'

Mỗi tiến trình gateway ghi một file mỗi ngày (UTC), nên sau 07:00 giờ Việt Nam hoặc sau khi gateway khởi động lại (cập nhật omp) thì chạy lại lệnh. Bỏ phần | jq … để xem nguyên dòng JSON.

Lịch sử request mọi ngày (mọi file log, kể cả sau khi khởi động lại)

sudo sh -c 'grep -h "\"auth-gateway request\"" /home/omprouter/.omp/logs/omp.*.log' \
  | jq -r '[.timestamp[0:19], .client // "(admin)", .format, .model] | @tsv' | sort | tail -50

Lỗi thường gặp

MãThân lỗiNguyên nhân và cách sửa
401{"error":"unauthorized"}Thiếu key, sai key, key đã bị thu hồi, hoặc gửi key qua x-api-key. Gửi Authorization: Bearer ogw_….
400gateway bearer token outside AuthorizationKey nằm trong URL hoặc header khác. Chỉ đặt key trong Authorization.
404Unknown model: …Model không tồn tại, hoặc key bị giới hạn model. Xem GET /v1/models bằng chính key đó.
403Key client gọi /v1/usage hoặc /v1/credentials/check. Các đường này chỉ dành cho owner.
429, 5xxlỗi của nhà cung cấpThường là hết hạn mức của tài khoản nhà cung cấp. Đợi giờ reset trong omp-gw usage, hoặc báo owner.
502Gateway đang khởi động lại (cập nhật omp, thường dưới 30 giây). Thử lại sau ít giây.

Quy tắc dùng key

  • Key chỉ dành cho người trong 8 Sync. Không đưa cho khách hay người ngoài, không bán, không dùng chung một key cho nhiều người.
  • Cất key trong trình quản lý secret hoặc biến môi trường. Không commit vào git, không dán vào chat, không đặt trong URL.
  • Lộ key: báo owner thu hồi ngay (omp-gw key rm), rồi lấy key mới.
  • Router không phục vụ đăng nhập gói Claude (OAuth của claude.ai): account pool của gateway ẩn mọi tài khoản như vậy, và guard dừng gateway nếu có login đó trong kho. Claude chỉ được thêm bằng API key Console của org, theo luật anthropic-compliance.
  • Điều khoản của từng nhà cung cấp vẫn áp dụng cho nội dung bạn gửi qua router.
  • Z.ai hiện là gói GLM Coding Plan (Pro), không phải API trả theo token. Z.ai ghi: "The GLM Coding Plan is strictly limited to use within officially supported tools and products. The subscriber shall not use the subscription benefits in any unsupported tools or scenarios." (FAQ, đọc 23/10/2026). Danh sách công cụ được hỗ trợ (Claude Code, Codex, OpenCode, Cursor, Cline, Pi…) ở trang này. Script, SDK hay sản phẩm của bạn không nằm trong danh sách: đừng chạy chúng bằng model zai/* của router cho tới khi owner thêm API key Z.ai trả theo token.

Vận hành (owner)

Trạng thái tổng

omp-gw status

Mọi login trong kho, theo nhà cung cấp

omp-gw accounts
omp-gw accounts --hours 168

Mỗi login (credential) một dòng: còn dùng được không, hạn mức riêng, và số request nó đã phục vụ (đếm từ log gateway). Nhiều login cùng một nhà cung cấp thì gateway tự chọn login cho từng request theo mức dùng và chuyển sang login khác khi một cái chạm hạn mức hoặc lỗi xác thực. Ngày 23/10/2026, ba key Z.ai lần lượt phục vụ 8, 28 và 8 request và báo y hệt nhau mọi hạn mức, nên nhiều khả năng là ba key của cùng một tài khoản: khi đó chúng dùng chung quota, thêm key không thêm quota.

Tự cập nhật omp

Timer omp-router-update.timer chạy mỗi 30 phút:

  1. Chỉ nhận bản stable đã phát hành ít nhất 24 giờ (OMP_SOAK_HOURS trong /etc/default/omp-router).
  2. Tải omp-linux-x64, so SHA-256 với digest của release, kiểm --version.
  3. Lưu bản cũ thành /opt/omp-router/bin/omp.prev và sao lưu mọi database của router (/home/omprouter/.omp/agent/*.db) bằng SQLite backup.
  4. Thay binary, khởi động lại broker và gateway, rồi kiểm: /healthz, /v1/models, và một request chat thật tới OMP_PROBE_MODEL.
  5. Hỏng bước nào thì trả binary cũ, trả database nào bị đổi schema, khởi động lại, và ghi phiên bản đó vào /var/lib/omp-router/bad-version để không thử lại. Nếu bản cũ cũng hỏng (nhà cung cấp lỗi, hết hạn mức) thì lỗi không nằm ở bản mới: file đó bị xoá để lần sau thử lại.
  6. Mỗi lần chạy, broker hoặc gateway đang tắt (kể cả bị systemd bỏ cuộc sau 10 lần crash) được bật lại.
  7. omp của agent trong terminal web là bản riêng, tự cập nhật theo omp, không do timer này.

Xem lần chạy gần nhất, chạy ngay

journalctl -u omp-router-update -n 30 --no-pager
sudo systemctl start omp-router-update

Thêm nhà cung cấp

Router có kho login riêng (user omprouter), tách khỏi omp bạn dùng trong terminal web: /login trong phiên omp thường của agent không thêm gì vào router. Thêm login cho router chỉ qua omp-gw; lệnh cần sudo, chạy được từ terminal web hoặc SSH.

  1. Đăng nhập bằng một trong hai cách (kết quả như nhau):

    Cách A, CLI: một nhà cung cấp theo tên, hoặc chọn từ danh sách

    omp-gw login deepseek
omp-gw login

    Nhà cung cấp dùng API key: lệnh in link trang lấy key rồi hỏi key; dán vào và Enter (lời nhắc này đã thử với deepseek ngày 23/10/2026). Danh sách tên: chạy omp-gw login không tham số.

    Cách B, TUI của omp

    omp-gw tui

    Mở omp của router; gõ /login, chọn nhà cung cấp, dán key, rồi thoát omp.

  2. Cả hai cách đều tự làm phần còn lại: tạm dừng gateway trong lúc đăng nhập, chạy guard, khởi động lại broker và gateway. Guard từ chối thì gateway đứng yên cho tới khi gỡ login đó.
  3. Kiểm tra login mới và model của nó:

    Kiểm tra

    omp-gw accounts
omp-gw models | grep '^deepseek/'
  4. Key tạo không có --models gọi được model mới ngay. Key giới hạn model thì tạo key mới, ví dụ omp-gw key add <tên> --models 'deepseek/*' (nhà-cung-cấp/* là mọi model của nhà cung cấp đó).
